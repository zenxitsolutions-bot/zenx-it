## Decisions made

- **Mirrored the existing `transport/` abstraction rather than replacing Resend.** Keeping three
  transports selectable costs one map entry and rules out a re-migration if Resend's domain
  verification is done later.
- **`smtpSecure` is derived from the port** (465 → implicit TLS, else STARTTLS) instead of
  defaulting to a constant. A fixed default is wrong for half of all providers, and the failure
  mode is an opaque connection hang rather than a clear error.
- **`auth` is omitted entirely when `SMTP_USER` is empty**, not passed as `{user:'',pass:''}` —
  nodemailer attempts AUTH with empty credentials in the latter case, which an IP-authenticated
  internal relay rejects outright. This rules out needing a separate "no-auth relay" flag.
- **The transporter is created once and reused.** `worker.js` drains in batches of
  `EMAIL_QUEUE_BATCH_SIZE`; reconnecting per message would mean a TLS handshake and AUTH round-trip
  each time and gets throttled by providers that cap connections-per-minute.

## Problems hit & how they were solved

- **Attachments would have been double-encoded.** `resendTransport.js` base64s the `.ics` because
  Resend's API requires it; copying that into the SMTP transport would have delivered a calendar
  invite no client could parse, since nodemailer does its own encoding. → Pass the raw string.
  Verified by decoding the attachment off the wire — round-trips to valid `BEGIN:VCALENDAR`.
- **Could not confirm delivery without a real mail account.** → Wrote a throwaway raw-socket SMTP
  server (scratch dir, not committed) and pointed a scratch server instance at it on port 4002, so
  the full `POST /api/auth/forgot-password` → queue → worker → SMTP path could be inspected without
  touching the live `.env` or sending anything externally.
- **`reminder_sent_at` errors looked like they might be caused by the email work.** They weren't —
  pre-existing schema drift, visible in the log from the moment the server was first started this
  session. Confirmed by the timestamps, then fixed by the migration.
- Dead end: tried to confirm the admin portal's live/demo mode by curling Vite's transformed
  module. `import.meta.env` is resolved at runtime in dev, not inlined, so the served source shows
